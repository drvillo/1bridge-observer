# 1bridge independent observer

Public, customer-operated pull observer for 1bridge governance evidence. This repository has a bounded pull client, process-local fixed-target verification, a test-only HTTP governance source, and a durable Postgres store for schema installation, pinned feed registration, fenced worker leases, provisional target fixation, evidence staging, cryptographically checked target acceptance, and quarantined replay findings. It does not yet run scheduled polling or produce signed audit coverage. A running health endpoint is not an audit assurance.

## Run locally

Use Node.js compatible with Next.js 16 and pnpm 10.29.3. Run `pnpm install --frozen-lockfile`, then `pnpm dev` for the local app or `pnpm build && pnpm start` for a production build. `GET /api/health` returns `{ "status": "up" }` to indicate process liveness. The static home page states the current scope.

Copy `.env.example` to a private environment file and supply customer-controlled values when integrating the next runtime phase. The configuration loader in `src/lib/config.ts` accepts an environment record at runtime; the bootstrap page and health route do not read it. `src/lib/source.ts` fetches a provisional head and exact checkpoint/leaf pages; `src/lib/verify-source.ts` replays one fixed target under the independent anchor pin in a single process and refuses incomplete budgets. Tests exercise this path against a local HTTP governance publisher. `src/lib/store.ts` uses `pg` to install `schema.sql` inside one transaction, register exact independently pinned feed bytes, claim fenced database-time leases, fix one exact provisional target, and stage contiguous source bytes with an idempotent cursor. Staging advances no accepted coverage. `acceptObserverTarget` replays retained bytes under the independent pin before committing accepted rows; `quarantineObserverTarget` retains a complete rejected attempt and unresolved finding so corrected source bytes can be retried. The replay path is bounded to 10,000 leaves and 32 MiB. `openObserverStore(DATABASE_URL, schemaName)` requires the named schema to exist; it defaults to `public` in a dedicated observer database. The setup caller must call `installObserverSchema` and `registerObserverFeed` before polling. No production route calls the source verifier or store yet, so no live independent coverage is claimed. Keep credentials outside source control. In a Vercel project, set the same values as environment variables. No cron job is registered until a real bounded poll route exists.

`SOURCE_BASE_URL` must be an HTTPS origin with no credentials, path, query or fragment. Only `NODE_ENV=test` permits HTTP loopback fixtures. `FEED_ID` is 64 lowercase hex characters. `ANCHOR_PIN` is the 64-character lowercase hex output of the authority library's `anchorHash(anchor)`, obtained through an independently authenticated customer ceremony. `SIGNED_ANCHOR` is canonical unpadded base64url of UTF-8 `canonicalJson(signedAuthorityAnchor)`. A signed anchor may be fetched from the source, but it must verify against the independently configured pin; never derive or replace the pin from source responses. The async `verifyObserverAnchor` routine verifies the pin, both customer key-possession signatures and feed identity, then returns the initial authorized provider checkpoint public key and key ID from the verified anchor. The old `CHECKPOINT_PUBLIC_KEY` input is removed because the pinned anchor already authenticates that key. `DATABASE_URL` must identify a Postgres database. `CRON_SECRET` needs at least 32 UTF-8 bytes.

The first-party authority package is pinned to immutable commit `57c441f430ca1c4616167a0f97a67a2c273e087c`. `pnpm-workspace.yaml` permits only that package's Git `prepare` build. A trusted operator must review upgrades before changing the commit and pin. The pull client treats a fetched target as provisional until the full signed history is replayed under the independently pinned anchor. `test/governance-v1.json` is byte-for-byte identical to the authority package's fixed public vector; the observer serves it over the fixture HTTP source and verifies the exact target. The root `schema.sql` and `bash test/schema.sql.test.sh` define and test the observer-owned Postgres tables in a disposable `postgres:17` container. To check DDL on a local Supabase Postgres container, set `OBSERVER_SUPABASE_CONTAINER` to its container name and run `bash test/schema.supabase.test.sh`. To check the runtime store against a local Supabase container, also supply a host-accessible `OBSERVER_SUPABASE_DATABASE_URL` and run `bash test/store.supabase.test.sh`. Both scripts create and remove a separate disposable database; they never install observer tables in the app database. No database-backed poller exists yet.

Run `pnpm test`, `pnpm test:integration`, `pnpm lint`, `pnpm typecheck`, `pnpm build`, and, with Docker available, `bash test/schema.sql.test.sh` to check this increment. `pnpm test:integration` starts and removes a disposable Postgres 17 container; the default `pnpm test` intentionally excludes real-database tests. [Architecture and implementation order](docs/architecture.md) describes the trust boundary, evidence ownership, planned verification path, and limits of source-only pulling.
