# Bounded source client verification profile

The `v1` pull transport lives in `src/lib/source.ts`. It is deliberately not an observer coverage certificate. `discoverFeedHead` verifies the operator's independently pinned dual-signed anchor, structurally parses the source's checkpoint, and labels the target `provisional: true`. It does not authenticate a rotated checkpoint signer or accept history. The process-local `verifySourceTarget` in `src/lib/verify-source.ts` fetches one fixed target, replays every checkpoint and leaf against that pinned authority, checks the exact discovered target bytes and returns a verified snapshot within an explicit leaf/checkpoint budget. It retains nothing across invocations. The bounded `pollObserverOnce` core now stages exact bytes and accepts a complete replayed target under a fenced database lease, but no production route invokes it yet.

The client uses the three fixed-target GETs in `docs/source-pull-contract.md`, exact canonical JSON envelopes and inner bytes, immediate predecessor checks, contiguous leaf positions derived from the request cursor, decoded streaming byte caps, timeouts, and redirect rejection. HTTP errors expose status without source response bodies; failures do not write observer state. No source credential convention or production secret was added while that decision remains pending.

The poller can distinguish `SourceHttpError` (status), `SourceTransportError` (connection, interrupted body, rejected redirect or timeout) and `SourceProtocolError` (malformed successful response, including canonical/shape errors and decoded size limits). A rejected redirect is classified as transport failure because native `fetch` with `redirect: 'error'` rejects before exposing its HTTP status. On a non-2xx response the client cancels the body without draining it, preserving the HTTP status even if the body never ends. These errors contain no response body or source URL. A protocol error is source nonconformance, not proof of an authenticated fork; a transport error keeps coverage pending.

`test/source-fixture.ts` is a loopback HTTP transport fixture with a real dual-signed anchor, provider-signed checkpoints and canonical Merkle-rooted bytes. Its two placeholder leaves are **not governance actions or revisions** and must not be used to claim an authenticated governance replay. The fixture override supports malformed pages, outages, delay, old heads and alternate heads. `test/governance-source-fixture.ts` separately supplies seven real mixed-governance leaves, two actor streams, a policy revision, provider-key rotation and signed invalid targets; `test/verify-source.test.ts` exercises the pinned process-local verifier against it, including missing genesis/target, a later skipped leaf, a different valid action leaf under the unchanged Merkle root, changed final signature and unavailable leaves. Neither fixture establishes a deployed or retained audit. The verifier's count limits are not an elapsed-time or peak-memory bound for a Vercel function.

Test-first evidence: the first focused run failed because `src/lib/source.ts` was absent. After implementation, disabling the nonterminal-checkpoint-page guard caused the targeted test to fail because an empty page resolved; restoring the guard made it pass. The classification tests then failed with the prior generic errors; changing the malformed-200 branch to a transport error made the targeted test fail again, and restoring it passed. On 2026-10-14, the full test, lint, typecheck, build and diff gates passed. The source suite exercises the real HTTP fixture, including a gzip body that expands beyond the decoded checkpoint cap. No deployed Vercel or real 1bridge source endpoint smoke was run.
