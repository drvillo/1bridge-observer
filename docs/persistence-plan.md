# Durable observer store increment plan

> This is a reviewed-before-code increment under the Superpowers test-driven workflow. It builds storage only. Until a source puller and authority replay invoke it, the observer makes no coverage claim.

**Goal:** Retain exact pulled evidence, a resumable cursor, leases and unresolved findings in customer-owned Postgres with crash-safe, competing-worker behavior. The same SQL must work against ordinary Postgres and a customer Supabase Postgres connection.

## Ground truth

- The repository currently has only a Next.js bootstrap, runtime config parser, static page and liveness route (`src/lib/config.ts`, `src/app/api/health/route.ts`, `README.md`). There is no database driver, migration, poller, accepted head, finding or audit statement.
- `docs/architecture.md` requires a customer-controlled Postgres cursor, immutable leaves/checkpoints, durable gaps/findings, short transactions and no provider service-role credential. The authority library's action/replay state serialization is not finalized; this increment must not pretend to verify leaf bytes.
- [node-postgres transaction guidance](https://node-postgres.com/features/transactions) requires one client for all statements in a transaction; the pool's separate query calls cannot form one atomic commit. `DATABASE_URL` is already parsed by `loadObserverConfig` but is not used by a route.
- Local Docker is available. A dedicated ordinary Postgres test container and a separate temporary schema/database in local Supabase can verify compatibility without touching app-owned tables. Credentials must never appear in test output or committed files.

## Journey and states

| Step | Caller | Durable state before → after | Failure |
|---|---|---|---|
| Install schema | Customer setup/CI | Empty DB → idempotent observer-owned tables and version marker | Unsupported older/newer schema refuses startup; app tables unaffected |
| Register feed | Authorized local setup | Out-of-band anchor pin, exact signed anchor bytes and source URL → one immutable feed identity row | Pin mismatch, conflicting feed identity or unsupported key never silently overwrites |
| Claim work | Cron/manual worker | Free/expired lease → owned bounded lease at database time | Competitor receives no lease; stale owner cannot commit |
| Fix target | Lease owner after signed discovery | No target or same target → immutable target checkpoint bytes/hash/size under lease and cursor CAS | Other target, stale lease or malformed checkpoint rejects; cryptographic authentication is the future caller's precondition |
| Commit verified batch | Future poll core | Expected cursor/version/target plus exact checked leaves/checkpoints → one transaction advancing cursor | Wrong start/target/version/lease, changed duplicate leaf, partial write or crash rolls back |
| Record finding | Future poll core | New evidence/gap → append-only unresolved finding | A later unrelated success cannot delete it |
| Resume | New worker | Committed cursor/target/evidence → next bounded batch | No repeated acceptance or skipped index |

These are persistence outcomes, not evidence-verification outcomes. A caller may only label a batch verified after authority-library checks; storage alone must never issue a signed coverage statement.

## SQL and API contract

Keep one `schema.sql` at repository root for the initial migration, avoiding a speculative directory convention. It creates an observer-specific version table and prefixed tables under the selected connection's current schema, without requiring `CREATE SCHEMA` privilege. Use parameterized SQL; quote no user-provided identifiers. For tests, select an isolated database or schema through the connection setup, not interpolated SQL. Reject wrong schema version rather than silently evolving a deployed database.

`observer_feeds` has immutable `feed_id` (64 lowercase hex), `anchor_pin` (64 lowercase hex), exact canonical signed-anchor bytes, `source_base_url`, and creation time. Feed registration parses and verifies those bytes through the published authority library against the separately configured expected pin; the pinned anchor supplies the initial provider checkpoint SPKI/key ID. The anchor may be obtained from the source, but the expected pin must come from independently authenticated customer configuration. `observer_cursors` has one feed row with `next_index` (nonnegative bigint **bounded to JS MAX_SAFE_INTEGER**), accepted checkpoint hash, fixed target checkpoint hash/size/exact signed bytes, version bigint and monotonically incrementing lease epoch, lease owner and database-time expiry. `observer_leaves` has `(feed_id,leaf_index)` primary key plus exact canonical leaf bytes and the RFC 9162 domain-separated `hashLeaf(leaf_bytes)` from the authority library (SHA-256 of `0x00 || leaf_bytes`, **not** raw SHA-256 of the bytes). `observer_checkpoints` retains exact canonical statement/signature bytes, checkpoint hash, size and predecessor; it never replaces a hash with changed bytes. `observer_findings` retains type, canonical evidence bytes, first/last seen timestamps and unresolved status; only a later explicitly verified resolution transaction may mark resolved. No free-form JSONB claim is treated as authenticated evidence. Add foreign keys and length/check constraints, and indexes for range reads and unresolved findings. Keep sensitive proof bodies out of SQL logs. Convert `pg` bigint strings to JS numbers only after explicit nonnegative/safe-integer validation; reject oversized DB values.

`openObserverStore(connectionString)` owns one `pg.Pool` and a clean close method. `installObserverSchema(store)` uses one acquired client and **one transaction** for all DDL plus the version marker, serialized by a fixed observer-specific transaction advisory lock. On first install it refuses any colliding `observer_*` object, then creates the exact tables. On repeat it checks version 1, the recorded schema-file digest and required catalog columns/constraints/indexes; `CREATE TABLE IF NOT EXISTS` alone is insufficient. Crash/rollback leaves no partial installed schema. `registerObserverFeed(store,config)` inserts one independently pinned **verified signed anchor** or checks byte-for-byte agreement on retry; no overwrite. This increment adds the user-requested first-party `@drvillo/1bridge-authority` library as an immutable commit-pinned dependency once its lifecycle API is independently reviewed, built and published; a cross-repo signed-anchor fixture must pass before registration is enabled. The config phase adds `ANCHOR_PIN` (customer-checked 64 lowercase hex) and `SIGNED_ANCHOR` (canonical base64url encoded signed-anchor bytes); the latter may come from the source but is accepted only against the former. `CHECKPOINT_PUBLIC_KEY` from bootstrap must match the provider key in the verified anchor, or be removed after a documented config migration. `claimObserverLease(store,feedId,workerId,duration)` uses database time and a conditional update that increments a per-feed `lease_epoch` on **every** claim, including same-worker reclaim; it returns an opaque claim containing that epoch, expected cursor version and database expiry. `beginObserverTarget(store,claim,checkpoint)` fixes a structurally valid target hash, size and exact signed bytes under the valid lease/version; it refuses a different in-progress target. **Cryptographic checkpoint authentication is a caller precondition**, not a store guarantee; no poller or coverage statement is shipped in this increment. `commitObserverBatch(store,claim,batch)` uses **one acquired client and one transaction**: lock cursor, check owner, lease epoch, `lease_until > clock_timestamp()`, version, target hash/size and start, verify every index contiguous, insert exact leaves/checkpoints, compare any existing row bytes on retry, advance cursor/version and commit. A final batch sets accepted head to the fixed target and clears target only when the future verifier provides a checked replay result matching exact cursor/target size; until then this increment must not expose a completion path that labels a target verified. An exact redelivery of a fully committed prior batch under a current claim returns `alreadyApplied` after byte-for-byte row/target comparison, without advancing cursor/version; partial overlap or changed bytes reject. `recordObserverFinding(store,finding)` appends without overwriting prior evidence. Reads return defensive copies/primitive values. A connection failure or serialization/deadlock conflict is reported for bounded retry by the caller, never interpreted as tampering.

The authority library's `HistoryFrontier` and authority replay state will be reconstructed from retained immutable leaves until a later versioned snapshot format is specified. This avoids inventing unsafe JSON serialization of an opaque trusted state. It is O(N) on cold restart; benchmark before claiming large-feed scalability. The cursor cannot certify a prefix merely because rows exist; only the future verifier may call commit after exact replay/proof checks. The public status page and `/api/health` remain liveness-only.

## Test-first plan

1. Add a real-Postgres integration test importing the missing store API; observe red. Add `test:integration` and exclude `*.integration.test.ts` from default `pnpm test`. Run an isolated ordinary Postgres container/database, plus a separate local Supabase test database/schema created and removed by the harness; never touch app-owned tables. Install schema twice, including simultaneous installers, and compare table/version/catalog state; wrong version, same-version mutated shape, object collision and failure between DDL/marker all fail without partial state. Implement smallest SQL/store module.
2. Test immutable feed registration from an independently pinned signed anchor, mismatch with `CHECKPOINT_PUBLIC_KEY`, source-provided substitute anchor, conflicting anchor/source and malformed feed/index/hash; test no secret leak. Deliberately remove one check and observe the targeted failure.
3. Test competing leases using two pools/clients, expiry with database time, stale claimant commit, **same worker ID reclaim with old epoch**, interrupted transaction rollback, target fixation/advance, redelivery of same batch, changed same-index bytes, duplicate checkpoint hash with changed bytes, noncontiguous batch, bigint overflow and concurrent target/cursor CAS. Assert the domain cursor/evidence rows, not query mocks. Use fault injection at the transaction boundary.
4. Test findings survive restarts and unrelated successful batches; no success route or report is added. Verify compatibility against ordinary Postgres and isolated local Supabase Postgres where available. Record exact versions and any unrun target.
5. Run `pnpm test`, `pnpm test:integration`, `pnpm lint`, `pnpm typecheck`, `pnpm build`, `git diff --check`, a compiled store import smoke and independent spec/quality review. Existing bootstrap route behavior remains unchanged. Later source verification must add a cross-repo fixture and may change the storage contract via an explicit migration.

## Principles, smells and verification

SRP: store owns durable facts and concurrency, authority library owns cryptography, future poll core owns fetch/verification. DRY: one SQL schema and one commit path. KISS: short Postgres transactions/CAS, not queues as evidence retention; no ORM or migration framework. YAGNI: no replay-state serializer or signed statement until a verified feed exists. Boy Scout cleanup is limited to touched files and separate from behavior changes. The first-party authority library dependency is explicitly part of the user's requested observer design and must be pinned to an immutable revision; `pg` is the sole proposed **third-party** runtime dependency, pending the user's explicit decision under AGENTS.md. This increment changes no 1bridge app source, so app gates do not apply yet.
